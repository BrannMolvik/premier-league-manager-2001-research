## Source 0x533370 per-side roster owner, 0x533A00 player row

Native `0x533270` invokes `0x533370` for BOTH sides, then original 1556-byte 0x6C1D00 staging and 280-byte 0x6C1D30 tactical staging before FastView modal. Native `0x533370` reads original match-side count DWORD `+0x5A4` (side 0) or `+0xB54` (side 1) and writes per-side 1556-byte scratch DWORD `+0xFC`. Side0 ordered player pointers begin in actual source match object `+0x04` and side1 `+0x5B4`; native `0x533A00` writes each ordered row starting at scratch `+0x104` in **72-byte/0x48 strides**. Caller must establish original pointer→world player identity; team or lineup guesses cannot substitute it.

`0x533A00` native rows: indirect name NUL-string through player+0x0C into row+0; indirect byte from player+0x08 into row+0x20; original player WORD+0x04 zero-extended into DWORD row+0x24; WORD+0x6E into DWORD row+0x28; original player subobject+0x248 pointer and `0x4EA300` three BYTE getters at subobject+0/1/2 into DWORD row+0x2C/30/34; player DWORD+0x14 bit11 via `0x41B490` into row BYTE+0x38. Source row+0x41..+0x44 comes from player+0x41..+0x44, +0x45/46 each copies player+0x40. The direct caller of `0x41E3D0` supplies *that same player's signed WORD+0x10*; its reachable source branch returns player BYTE+0x70, stored to row+0x47. Do **not** infer row byte +0x47 from the method's alternate +0x76 branch without its actual call arguments.

The eight original status bytes at row+0x39..0x40 each derive the side match byte at `+0x7C+0x4C*ordinal` / `+0x62C+0x4C*ordinal` and a nonzero test of each respective byte+5..12. The source sequence `neg/sbb/and 4/add 8` gives score `position - 5 + (12 when flag!=0 else 8)`, then clamps to 0..15 inclusive before writing each byte. No assumption about the real meaning of these fields is made.

## Original header 0x533480, formation mapping 0x5339C0 and option 0x533AB0

Native `0x533480` receives actual original club identity and the side scratch buffer. Source `0x5337C0` determines whether club WORDs+0x84/86/88/8A copy into scratch WORDs+0xD4..DA or four zero words. This predicate is **not** inferred from league membership: it also consults native external state, and the helper requires a qualified original boolean result. Original club direct BYTEs +0x44/47/4A–4C/56–58 build two four-byte groups each duplicated at scratch+0xDC/E0/E4/E8, including source-wrapping +1 at the first member. Further original bytes +0x45/50/51/48/5C/5D/46/53/54/49/5F/60 are copied to scratch +0xEC..+0xFA with intentional +0xEF/F3/F7/FB holes untouched. Source full header ALSO writes native-derived text at +0 and +0x40, pointer metadata at +0x80/84/88, and formation mapping at +0x8C..+0xD0; these are not resolved solely by the direct-fields helper.

When native `0x4037B0` reports a formation owner, `0x533480` reads three ordered WORD ID groups from `0x403850` source +0x664 / +0x66C / +0x668, with counts at +0x207 / +0x209 / +0x208. Native `0x5339C0` scans staged player DWORD IDs at scratch+0x128+0x48*ordinal and writes the **first matching** row ordinal into the group's next DWORD at scratch+0x90 / +0xA8 / +0xC0. Missing player IDs do not increment group counts, duplicates in a formation list can repeat an ordinal. Group count DWORDs are scratch+0x8C / +0xA4 / +0xBC. When formation owner absent, source zeroes these three counts without reading formation list pointers. Each original group output allocation holds five DWORDs before the next header region; unqualified larger source groups fail closed rather than silently overflowing adjacent fields.

Native `0x533AB0` normally returns **11**. It first resolves the corresponding original club through `0x405890` and checks club WORD+0x18; zero immediately returns 11. Otherwise `0x62AC80` resolves a distinct owner+0x4C object; nonzero virtual+0x30 result returns 11. On virtual-result zero, negative owner signed WORD+0x20 returns 11; nonnegative index uses native global `0x876C50+64*index`, checks the computed pointer nonzero and returns registry BYTE+0x2B. The helper requires the original conditional owner fields, real pointer gate and original registry-slot bytes as inputs; no current-game-team heuristic supplies these. The original source stores the result as a DWORD at scratch+0x100 after `0x533480`.
