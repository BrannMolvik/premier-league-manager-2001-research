- New `reconstruction/original_eamail_mailbox.py` holds `OriginalDeliveredEAMailboxes` — a registered-user ordered key tuple (max six), **separate mutable mailboxes** keyed by the effective native recipient, and an increasing **internal stable node serial**. This serial is strictly a compatibility snapshot surrogate, **never a claim about original PE native pointer addresses**. Per-user delivered order is append order; no cross-user merge or guessed PEAMail sort/filter.
- Only the source-qualified `EAMPlayerAskTransferListsub` recipient/sender envelope subset is accepted. The explicit `deliver_source_ready_transfer_request` method checks a **source supplied** stable envelope identity, original scheduled due date, concrete `+0x3C` class readiness booleans, and captured *producer-time* effective manager key. Null readiness rejects, false skips delivery, future due rejects. A registered recipient may receive a tail-appended record; an unregistered recipient gets **no fabricated mailbox or broadcast**. Duplicate same-source-event append to one user is rejected. Critically, **no currently running original game path invokes this new method**: the true transfer class `+0x3C` producer and pending-event lifecycle still require independent source implementation.

Original status semantics, message body, native raster and mouse acceptance remain explicitly **false/not decoded**; no synthetic welcome mail or missing-event conversion.
