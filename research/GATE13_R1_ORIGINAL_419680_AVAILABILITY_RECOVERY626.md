## Source reachability: order matters

Original `0x5127A0` uses two calendar searches per match owner, saves the result (which can be **NULL**) at stack+0x28, and walks each side's players. It calls original `0x419490` first over signed roster count+0x294 from ushort player IDs at side+0x244 (source return/countdown, potentially clears native status bit1 and emits events). It then processes individual active-row incidents via `0x4197C0` (PR725 covers a bounded arg2=0 subset), optional row+0x4A `0x41A5B0`, and finally at **0x5128EA–0x51292A** walks the ORIGINAL side roster again, resolving player objects from global 0x875644, passing **the same calendar lookup pointer, including NULL**, to `0x419680`. Consequently 419680 must not be moved before the original 4197C0 incident or treated as a report-only calculation.

Direct original `0x419680–0x41971C` static source:

- If the match-calendar lookup argument ESI is **zero**, original tests only native player BYTE+0x13B (FA countdown). If nonzero it ORs native status DWORD+0x14 with bit1 (0x02); otherwise returns unchanged. It does **not** call original competition virtuals, date getter 0x510A20 or registered-user predicate 0x417340 in this NULL path, even if UEFA+0x13E is positive.
- If ESI is **nonnull**, source invokes original ESI virtual+0x18 to get a match pointer, traverses match+0x4C competition owner with `0x4F3DC0` and calls the competition owner virtual+0x18. If nonzero, it invokes ESI virtual+0x18 **again**, re-resolves competition owner+0x34 and checks whether this is exactly 1. UEFA owner==1 is a distinct early branch: if native UEFA BYTE+0x13E nonzero, OR status bit1 and return; if zero, return **without FA fallback** even when FA+0x13B nonzero.
- Non-UEFA/zero-v18 branch instead checks original FA BYTE+0x13B. Zero skips all date/user work; nonzero calls original `0x510A20`, which computes a raw signed date through the reachable `0x510300` context using source match+0x10 + base+0x08. Its actual output is required, never synthesized from the model's Python calendar. Source signed CMP compares player DWORD+0x160 to the reached date. Only when `due<=date` original calls `0x417340` read-only registered-user test; **its AL result is ignored** before ORing player status+0x14 bit1. Unlike eligibility for a mail/event class, this status bit is set even when no human manager owns the club.
- Native status OR is idempotent but preserve all other DWORD bits. No RNG, native heap event insertion or original Inbox mutation occurs inside 419680. External ESI/competition virtuals and original 510300 date lookup may affect world outside this bounded function and remain **unverified**; never claim source-complete global calendar parity from this receipt.
