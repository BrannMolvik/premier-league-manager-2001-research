## What the source actually does

- Actual 0x5128B2–0x5128B8 owner loop calls native `0x4197C0` with the reached player ECX and stack: incident BYTE row+0x48 (`EBX`), incident BYTE row+0x49 (`EBP`), opposing side pointer, original match pointer. After that call, optional row+0x4A flag triggers **separate original 0x41A5B0** which may mutate world/queue.
- `0x4197C0` calls original 0x4085D0 (the native status/role/category/club world transaction mapped in PR724) **only if original EBP/arg2 is nonzero AND player DWORD+0x14 bit4 is zero**. This new bounded integration deliberately handles only `arg2=0`, so native 0x4085D0 and its role/club world writes cannot silently be skipped on a path where they would occur.
- Original match+0x4C leads through `0x4F3DC0` source competition-owner chain to a virtual+0x18 called **twice**, independently. If the first result is nonzero and its additional retrieved owner+0x34 is 1, an early `0x417EE0` check is skipped. Otherwise original `0x417EE0` is reached when arg1=arg2=0 and native player BYTE+0x13A is nonzero. Its own result is unused in this branch, but source model refuses this extra native read without a separate reached proof.
- If the **second** original competition virtual+0x18 is nonzero and its fresh owner+0x34 equals 1, source resolves third owner+0x14 and calls original `0x41A250` UEFA incident, then **immediately returns before** 0x5112E0 and FA/general disciplinary continuation. Existing exact source model (PR719/720) is composed only when `arg2=0` and the wrapped +0x13D accumulation is at most 2, meaning neither original 417340 call nor either 585750/585AD0 pending event is reached. This path can update original source-native BYTE+0x13D without altering generic RuntimePlayer or Inbox.
- On the other branch, original `0x5112E0` calls competition owner virtual+0x30, masks its EAX to low BYTE, and if nonzero calls exact original `0x41A490` (already source-proven in PR717). It adds min(2, arg1+2×arg2) into BYTE player+0x144, wrapping modulo256, then conditionally calls original 417340 if **post-add** value exceeds 1. The new player-world leaf rejects that callback-bearing case, so it never silently loses the original world-facing result.
- For all non-UEFA cases, original `0x419916` enters its general discipline continuation only if arg1/EBX is nonzero. It zeros player+0x13C. Before adding arg1 into BYTE player+0x139 and +0x13A modulo256 it tests the **old** BYTE+0x139 % 13 against 12, which can update native FA+0x13B, initialize raw +0x160 date and call 0x41A060. The new leaf rejects this entire threshold, not merely the message. It also rejects any post-add BYTE+0x13A at least 5 because native then subtracts 5 exactly once, may update FA+0x13B and call 0x4199E0. When neither threshold is reached, the only original player writes are verified +0x139, +0x13A and +0x13C reset, and optional +0x144 from 41A490.
- Original competition virtuals and `0x4F3DC0` linked-owner accesses may have world side effects not established by these receipts. The model does not execute them; it requires **separately actually reached before/after original full player bytes to be identical** across the competition calls and exposes `external_competition_virtual_world_effects_unverified=true`. The original match+0x4C root pointer and conditional category/context results are separately supplied source snapshots; these do **not** certify whole-game world changes, linked getter side effects, or original native execution. This is an explicitly scoped **player byte** step, not completion of the parent match transaction.
