## Original native 418050 AL control flow (bounded, source exact)

Original 418050 entry uses signed original player WORD+0x10 and original player BYTE+0x14:
- Initial **BL = ((player+0x14 & 7) != 0) OR (signed player WORD+0x10 != full signed/unsigned 32-bit team key)**, with an exact full DWORD comparison. The source signed word is sign-extended before compare.
- When original dynamic owner pointer argument2 is zero, jump to final 41B490 with no owner callbacks.
- When nonzero, **always call original 41B360**, which returns `(player DWORD+0x174 >> 8) & 1`. If zero, skip all later owner logic but retain that original leaf call.
- When bit8 nonzero and original owner DWORD+0x34 **equals literal 1**:
  1. Call original `4F8E40(owner, player WORD+4, team key)`. Returned AL nonzero sets BL=1, but AL zero never clears an existing BL.
  2. Call original `419350(player,&first_local)` and dereference returned local signed DWORD. If negative, stop this branch before checking mode globals.
  3. For first local nonnegative, inspect native DWORD global **8755E8**. Only literal 1 or 2 continue; 1 selects original signed threshold global **8755EC**, 2 selects **8755F0**. A second `419350(player,&second_local)` result strictly **greater** than that threshold sets BL=1. Signed comparison and the exact call/skip order matter.
- When bit8 nonzero and original owner DWORD+0x34 is **not** 1: call native owner's virtual+0x30. Returned AL nonzero skips later 4F8E40. On AL0, call 4F8E40 and set BL=1 only on AL nonzero.
- **Every path** reaches native `41B490(player)` (reads DWORD player+0x14 bit11). If false, return BL exactly. If true, call `41B4D0(player)`; this callee may execute **417A20** and affect original world, so actual returned owner pointer and source bytes from *after* that callback are mandatory. Native `4E9BE0` returns AL1 if signed global current-day `9847FC` is **less than or equal to** signed owner DWORD+0x14. If AL1, 418050 returns the previously accumulated BL; if AL0 (expired), original **forces return AL1 regardless of BL**. The source uses `setle`, not an unsigned time comparison.

Original `419350` itself may traverse `4EBE80` and mutate original date/owner outputs, `4F8E40` delegates to `4E9710`, native virtual+0x30 is dynamic and `41B4D0` contains roster/expiry-world effects. Therefore **none of these callback outcomes are derived from the modern reconstruction's team, fitness or date**. The new implementation merely source-projects a complete **already-reached** original callback result sequence, strictly rejects missing/extraneous/unvisited callback data, preserves the original initial vs at-41B490 player snapshots, and records the precise original native sites that would be reached. All receipt booleans `native_418050_executed`, `original_dynamic_callbacks_executed`, `live_player_or_match_world_modified` remain FALSE.
