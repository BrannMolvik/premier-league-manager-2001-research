# Recovery566: original SupportStart Cancel is not a pre-staging rollback

**Original reference:** privately supplied and SHA-256 checked original `footballmanager.exe`, 4,714,541 bytes, SHA256 `833bf95e92a1c76ade47106f8ad7d3ca307069b7e5778a7067cd0658838b7cc3`. All statements are confined to static x86 instruction/source evidence; no original game process was launched and no genuine Windows11 GUI was observed. Gate13–17 OPEN.

## What the original does before the modal even appears

Normal first selected-human TeamSelect at `0x4D8F75` constructs six source types `(1,2,3,4,5,13)` via `0x4C9CD0`, initially held in DBRUser current staff list `+0x5D0` and global staff list `0x875600`. The same event immediately invokes `0x4D8F7F -> 0x4DA4F0` BEFORE the later `0x4D91C0 -> 0x450BB0` SupportStart modal. Native `0x4DA4F0` traverses source indices `6..0`. For each nonnull generated staff pointer, source `0x4DA536 -> 0x4CA070` **appends the staff pointer** to its inactive type list (1–5 into selected user+0x5B8, 13 into +0x5C4 via `0x4CA092/0x4CA0A6/0x4CA0C7`). Then `0x4DA55C -> 0x4D1880` unlinks that staff from the current+0x5D0 list, and `0x4DA583 -> 0x4D1880` removes it from the global staff list when found. It stores source slot pointer and original flag `1` at `0x4DA592/0x4DA594`. This **pre-modal transition is real native linked-list mutation**, not a preview or a hypothetical renderer.

Normal first-user modal-entry staff pointer lists therefore differ from the lists just after staff construction. An editor implementation must not automatically assume its entry snapshot is the original pre-staging list or reset the staff to pre-staging nodes merely because the user presses Cancel.

## What Cancel and Apply demonstrably do

Original nested event1 at `0x4D061F..` writes modal result0 and calls original close without executing `0x4D0830`. Event2 invokes virtual+0x4C (`0x4D0830`) before storing result1 and requesting close. Only the Apply routine begins with resetting original global/list owner flags `0x875600` and user+0x5B8/+0x5C4/+0x5D0 at `0x4D0844..0x4D086F` and thereafter iterates all 7 staff slots `6..0`, committing source selection flags and actual linked-list destinations. These are **owner flags**, not wiping list node heads. The original PSupportStart destructor `0x4CF790 -> 0x4CF7B0` destroys modal UI child members, including 7 row widgets via `0x66820D` and `0x4D89E0`; no bounded *direct* destructor call to full staff Apply `0x4D0830` was found. This does not prove every native Cancel destructor, callbacks, original global event queue or TeamSelect outer follow-on has no indirect staff side-effects. A full native modal/return/teardown audit remains open.
