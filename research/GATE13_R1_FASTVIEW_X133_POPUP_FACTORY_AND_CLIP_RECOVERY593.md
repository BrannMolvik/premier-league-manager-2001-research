## Original owner, actual source and effects

Prior merged PR669 source proved x133 child array `screen+0x263C+0x44*row`, native vtable `0x7CB010`, virtual +0x98=`0x52D120` and +0x9C=`0x52D190`. Recovery593 directly rechecked the original disassembly:

- Native `0x52D120` requests 0x18C-byte memory via `0x668140`, and if nonnull passes `[child+0x38]` original list owner into `0x52D1F0`; if allocation fails returns null. This is factory allocation, NOT popup activation, current selection or screen coordinates.
- Native `0x52D1F0` invokes `0x448310` base constructor, retains supplied list pointer at newly allocated popup +0x68, zeroes 25 DWORDs at +0x7C, initializes control fields and children at +0x10C and +0x13C. Neither text choice nor pointer event belongs to this evidence alone.
- Native child virtual+0x9C `0x52D190` reads parent through `[child+0x24]`. Its first value is `[child+0x10]+[parent+0x0C]`, its second `[child+0x0C]+[parent+0x10]`. It reads clip context offsets +0x70 (x origin) and +0x74 (y origin). It caps the first sum only on `origin_x+width>800`, setting `width=800-origin_x`; similarly caps the second only for `origin_y+height>600`, setting `height=600-origin_y`. It passes six arguments `(width,height,origin_x,origin_y,4,1)` to `0x653320`. This routine is a source drawing clip; it does not independently establish native popup hit testing, click acceptance, or option selection. It does not show a negative/left/top clamp.

## Recovery593 additional original popup Escape event route

Further direct original disassembly of 0x52D350..0x52D362 proves a native popup key handler compares incoming WORD against 0x1B (Escape). On that key ONLY it pushes WORD sentinel 0xFFFF to 0x6539F0; unrelated keys return without this call. Native 0x6539F0 masks the event value to 16 bits, obtains control+0x64 event-owner pointer, and dispatches an event code 0x400 to 0x659650 with the sentinel and a zero argument. **This proves an Escape-to-owner event route, NOT that the parent modal closes or that edited data are reverted.** Actual handling of 0x400 and source owner identity must be resolved before wiring a real cancel key. Static source instructions matched private authenticated original PE; no original process run.

## Recovery595: full original Win32 modal result / dropdown Escape source chain

**This section supersedes the earlier statement that Escape's receiver is unresolved for the specific x133 control.** Its receiver, full synchronous Wait/return boundary, and child status effect are now source-proven; other match-level exit/rollback and actual option mouse hit remain UNKNOWN. The same owner-authenticated original 4,714,541-byte PE32 with expected SHA256 was statically re-read, never executed.

1. Native x133 child setup `0x5D71A0` pushes **global UI controller address 0x877960** (at `0x5D71AD`) as the eighth input to `0x651A50` (call `0x5D71CD`). Constructor `0x651A96` writes that address to child `+0x30`. Parent x133 array 11×0x44 children and derived `0x52D0D0` input were separately proven by merged PR669.
2. Original global GUI controller constructor `0x532570` initializes native vtable **0x7CB294** (`0x53262F`). Its virtual `+0x20` is **0x532650**, proven from private original .rdata; virtual `+0x00` is **0x532B80**.
3. Native selected child input `0x651AC0` invokes its derived virtual +0x98 -> `0x52D120` factory, its virtual +0x9C -> `0x52D190` draw clipping, then **the controller pointer at child+0x30 virtual+0x20** at `0x651AF2..0x651AFA` with the newly made popup and zero flag. Controller `0x532650` forwards to `0x654210` (call `0x53266D`). The original `0x654210` sets popup+0x64 to the owner/controller, installs popup at `0x6542B0`, then calls controller virtual +0 (`0x65425C`) -> **0x532B80** modal queue pump, returning its result in EAX.
4. Original popup vtable **0x7CAC64** has `+0x34=0x52D350` Escape handler and `+0x20=0x446690` separate nonzero-argument sentinel producer. ESC WORD 0x1B or nonzero virtual+0x20 callback triggers a **0xFFFF** event via `0x6539F0`. `0x6539F0` masks wParam to WORD, follows popup+0x64 owner and calls `0x659650`. Original imported thunk **0x7BD2D8 is USER32.PostMessageA** (verified in original PE import directory, not SendMessage). `0x659650` obtains HWND from controller+4 and posts `(HWND, WM_USER=0x400, wParam=0xFFFF, lParam=0)` asynchronously.
5. **Original `0x532B80` is the connected modal pump.** It calls `PeekMessageA`/`GetMessageA`, checks MSG.message `0x400` at `0x532BBF`, returns **MSG.wParam** at `0x532BF9` without TranslateMessageA/DispatchMessageA in that case, while unrelated messages follow their ordinary dispatch path. Thus when the queued Escape event is delivered, it resolves the same modal call back through `0x654210→0x532650→0x651AC0` as DWORD **0xFFFF**.
6. Native `0x651AC0` compares EBX modal result with 0xFFFF at `0x651B0B`. For sentinel, sets child BYTE+0x40 to 1, leaves prior child+0x3C selection unchanged and skips valid selected-index/list pointer writes. Non-sentinel result sets child+0x40 to 0 and stores selected DWORD to child+0x3C, optionally updating the selected list. Separate later source `0x52EBDC` checks invalid status before mutating match-side state. Original parent callback may still be invoked for 0xFFFF under separate event+0x20/input-flag gates; **do not model ESC as globally suppressing all callbacks or canceling an entire match**.

Independent owner original verification: 33/33 exact instruction signature matches for popup factory/draw/event sender/pump, plus 17/17 exact native modal owner/path signature matches and 4/4 exact vtable method pointers. The source-byte tests are opt-in with `FM2001_ORIGINAL_EXE` and never vendor the original executable. ## Recovery595 source completion: original nested option row factory and posted selection index

Still on same WIP branch `worker/gate13-r1-fastview-popup-option-layout-source-595`, after PR670 merged source-bounded ESC. - Native popup vft+4 `0x449300` creates its nested list at popup+0x13C (vtable **0x7BFD5C**) and calls nested `vft+0xB0=0x446740` with original 8-byte list-item stride, 15px native pitch, count popup+0x6C, content height `15*N`, inner width popup+0x78. Adapter `0x446740` invokes original list allocator `0x6510F0`.
- Native `0x6510F0` allocates a vector of **4+0x30*N bytes** and initializes N native row controls using ctor `0x651280` (derived vtable **0x7D8118**). For each ordinal it invokes list parent `vft+0x9C=0x449470` to create rich content, and stores child/index at item **+0x68 = list_parent+0x3C+ordinal**, with list-parent pointer at item **+0x08**. Source read-only model `source_fastview_popup_native_option_rows_6510f0` reproduces only ordinal, vector element offset and native index, not pointer behavior.
- Original `0x449470` allocates a **0x17C-byte** rich row item from original `0x668140`. It computes source data pointer from owner+0x4C (the original list) and **`source_item_ptr = list + 8*ordinal`** at `0x4494B7`, saves it at item+0x70 at `0x4494D1`, constructs nested row controls +0x10C and +0x13C and installs final derived item vtable **0x7C0334** at `0x449551`. That exact original vtable's virtual **+0x10 = 0x653A10** (verified pointer from PE .rdata).
- Original source `0x653A10` receives input callback DWORD and returns without posting when that arg is zero; for **nonzero**, reads a **WORD at item+0x68**, follows item+0x08 list parent, then list_parent+0x24 popup owner, and invokes `0x6539F0`. As previously source-qualified, `0x6539F0` posts `WM_USER=0x400`, wParam selected index WORD, to original modal `0x532B80`. Modal returns that index to native x133 `0x651AC0`, which stores status0 and selected DWORD. This **source-closes a native item activation → posted index → dropdown selection result once invoked**, not the upstream actual mouse coordinate hit to item callback.
