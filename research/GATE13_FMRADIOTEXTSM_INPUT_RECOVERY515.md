## Recovery 517: strict native control pointer-target gates (static disassembly)

**11 October 2026 KST; same canonical original PE** `833bf95e92a1c76ade47106f8ad7d3ca307069b7e5778a7067cd0658838b7cc3`, rehashed in the working container this recovery. This is a separate native control-framework source confirmation, **not** evidence that the original game's physical WM_LBUTTON callback reaches radio activation or that the current Windows host accepts it.

### Exact original framework code

1. The original `fmRadioTextSm` vtable at `0x7D6AB8` has pointer-related slots `+0x84 → 0x64FBE0` and `+0x50 → 0x64F5D0` (which dispatches `+0x54 → 0x64F5B0`). The comparator at `0x64F5B0` returns bit8 of control `+0x18` exactly. `0x64FB20` is also called by the base pointer-event notification path. Do not call the latter 'a radio click' by itself.
2. `0x64FB20` requires `(control+0x18 & 0x3)==3`, then checks `x >= +0x08`, `x < +0x10`, `y >= +0x0C`, `y < +0x14`; *both low edges inclusive, high edges exclusive*. It then calls child `vtable+0x50` and, only if accepted, sets global active pointer `0x984814 = child`. A failed test clears the global only if that same child previously owned it. Sibling routine `0x64FB80` uses the same bounds/state gates but child `vtable+0x48`, and updates `0x984818` (another pointer owner). These are distinct owner caches, not proof of click-to-event.
3. `0x64FBE0` itself compares event coordinates to control `+0x08/+0x10,+0x0C/+0x14` with the same half-open boundaries, then calls child virtual `+0x18` with argument 1 and may notify parent callback `+0x2C`. Out-of-bounds handling consults flag bit3. The `PLeagueFixtures` parent `+0x2C` is `0x42DE20` (trivial return), so this path alone **does not select a League**.
4. `0x5D4790` is a *separate* parent-child virtual-event broadcast: child vector `+0x2C/+0x34`, entry mask bit2 `0x4`, child `0x64F570` control-state bit0 gate, child virtual `+0x6C → fmRadioTextSm::0x5D4AC0`. It has no local rectangle comparisons. This independently rejects equating `0x5D4790` itself with a rectangle hit test. In the radio handler, `+0x18` bit1, state `+0x38`, source event ID `+0x20`, selected bit `+0x40` and parent callback `+0x0C/+0x10` control activation. The original `PLeagueFixtures` event switch is `0x46E040`.
5. Parent-child rectangle handling `0x5D4680` instead walks entry-mask `0x1`, intersects four edges of parent and child, and dispatches child virtual `+0x64`; this is a clipping-region traversal, **not** proof of a click. Parent child masks `0x2`, `0x4` and `0x10` are processed by different traversals `0x5D4740`, `0x5D4790` and `0x5D4860` respectively. The presence of valid radio rectangles does not prove topmost/occlusion eligibility.
