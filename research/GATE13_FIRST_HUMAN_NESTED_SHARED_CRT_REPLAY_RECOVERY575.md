The existing original TeamSelect user-birth direct-RNG **test-only** replay already consumes 26 original name draws then (omitting native side effects via explicit acknowledgement) 72 six-staff draws. Its first global event queue drain at `0x4259B5` occurs BEFORE those user nested draws, and the second drain at `0x412F1F` after manager binding and before staff. Updated `reconstruction/original_supportstart_teamselect_user_birth.py` accepts an **optional, source-validated, caller-provided `OriginalNestedRandomBranchProjection`**. Only with explicit source allocation branch flags, it advances the SAME caller-owned RNG once at bound20 per successful child, exactly after names before staff. It preserves existing legacy direct 98-draw tests/receipt semantics, provides a separately marked `nested_user_source_rng_call_count` and `modeled_source_rng_call_count` (101 on hypothetical all-success path), and verifies immutable source receipt fields against a freshly constructed canonical projection before ANY RNG consumption. Forged counts or a forged live-checkpoint flag are rejected. No original nested player-record values, manager ownership, branch success results, queue events, GUI input or new seed are invented.

Three new regression methods cover 26+3+72 ordering on one RNG owner, individual allocation branches, and invalid/forged receipts causing zero draws. The strict `acknowledge_omitted_native_event_and_binder_effects` test-only guard remains mandatory and DOES NOT authorize live GameState even when 101 bounded calls are modeled. Actual user selection will require a true runtime queue/CRT source checkpoint plus qualified original UI. This is a source-bounded integration helper, not Gate13–17 completion or Windows11 GUI release.
