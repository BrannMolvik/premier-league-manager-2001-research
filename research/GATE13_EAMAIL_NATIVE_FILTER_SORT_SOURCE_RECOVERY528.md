## A. Original filter owner: ten mutually selected native controls, exact predicate

`PEAMail::0x472680` probes up to **ten** option controls beginning at **panel+0x64C**, stride **0x4C**, invoking native `0x651AB0` until the first nonzero selection; selected numeric index 0..9 is held in EBP. When none is selected it defaults to **index 0**. The filtered rows are generated by **two walks of the selected user's DBRUser+0x6B4 delivered linked list**, not from pending MPM events:

- **Index 0:** only include a record when **`((record+0x08 >> 2) & 1) != 0`** (source `0x4726E9..0x4726F9`, second identical pass `0x47274B..0x472761`). It is not safe to label this bit as "read" or "unread" until original UI and producer/consumer semantics close.
- **Index 1:** include all delivered records, unconditionally (source `0x4726D9..0x4726F6` and `0x472744`).
- **Indices 2..9:** include only when native EAM **`record+0x0C == selected_index`** (`0x4726DC..0x4726F9` and `0x472735..0x47273C`). These are direct numeric EAM category IDs, not invention of category labels.
- `PEAMail+0x6C` becomes the count and `PEAMail+0x68` receives the separately allocated array of selected EAM pointers via `0x668140`. The first pass sizes the buffer; second fills it in per-user delivered list order. No generic global messages, guessed dates, synthetic categories or current-user-only queue contents are substituted.
