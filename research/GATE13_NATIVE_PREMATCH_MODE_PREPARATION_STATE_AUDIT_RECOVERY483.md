Commands to reproduce the relevant original code as read-only disassembly: `objdump -d -M intel --start-address=0x5130f4 --stop-address=0x513158 footballmanager.exe`, `--start-address=0x632b20 --stop-address=0x632b63`, `--start-address=0x62abd0 --stop-address=0x62ac61`, `--start-address=0x62ac90 --stop-address=0x62acd3`, `--start-address=0x49ab50 --stop-address=0x49ac06`, and `--start-address=0x533120 --stop-address=0x5331be`.

The source-important discovery is **not simply the previously known four-way presentation choice**: `LeagueMatch::0x513010` takes an additional **mode-dependent match-context preparation path** before it reaches the remaining match method calls and presentation dispatch. At `0x51310A..0x51312C`, the human/presentation bit0x10 and not-completed bit0x20 enter a genuine `PPreMatch` modal if `0x875680` settings owner is NULL or mode `0x877530` is sentinel5 (Recovery474 already established this; do not claim it new). The **new exact conditional code** is:

| Source selection after optional modal | Original `0x51312F..0x51314E` | Proven immediate state mutation |
|---|---|---|
| **0 = 3D Match**, **1 = 3D Highlights** | Branch `0x51312F test eax; 0x513131 je 0x513144` or `0x513133 cmp eax,1; je 0x513144`; `0x513144→0x632B50` | `0x632B50` at **0x632B55** explicitly writes **byte [match context+0x1145]=0**, then calls shared `0x632B20` |

`0x632B20` stores the pointer as global `0x981C78`, invokes `0x62AC90`, `0x62FBC0` and `0x667E20` on the same supplied match-processing context. This is actual preparation work, **not a view-only label change**. The fresh match-context initializer `0x62ABD0` sets **byte+0x1145 = 1** at `0x62AC3F`. During shared preparation, `0x62AC90` reads byte+0x1145 at `0x62AC98` and after clearing other fields branches: if byte is zero, **writes dword [context+0x1150]=3** (`0x62ACC0`); if nonzero, **writes [context+0x1150]=0** (`0x62ACCC`). Under a freshly initialized, otherwise unmodified context, the 3D branch therefore reaches the zero-byte / value3 entry; the direct FastView/Quick route reaches nonzero-byte / value0. Other source writes **do exist** (`0x63005E` sets byte+0x1145=1 when `context+0xD3C==0`), so this **must not be promoted into a permanent global “3D always 3, Quick always 0” rule** outside this exact moment.

This byte is a real downstream branch input, not unused metadata: `0x62E130` at `0x62E139..0x62E141` branches on it, and `0x62E2F0` at `0x62E2F8..0x62E301` likewise branches on it. The **football/gameplay meaning of these preparation and downstream functions remains UNKNOWN**; neither RNG effects, final score impact, injury behavior, field labels nor presentation-frame behavior is asserted from these data writes alone.

The conditional shared preparation runs **before** source `0x513153` match vft+0x28 callback and the later `0x51325D..0x513294` renderer-selection cases (0/1 `0x533D80`, 2 `0x5331C0`, 3 no wrapper). Original `0x533120` runs the actual `0x499C30` panel modal and **unconditionally copies** selected global `0x877530` into active match context+0xD3C at `0x533199` after `0x532650` returns; it does not visibly test the modal's return value in the wrapper. `0x49AB50` only accepts child IDs **1–4**, maps them to mode **3–0** and `0x49ABA0` writes the global / signals modal owner / closes. **Exit/cancel and stale sentinel5 behavior require additional proof; they are not treated as an accepted mode.**
