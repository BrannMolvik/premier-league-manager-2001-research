2. **Scheduled/event owner**: global `0x947AA8` holds pending events (not every entry necessarily mail). The `MPMEAMail` virtual `+0x10→0x5CFA20` checks underlying EAM record virtual `+0x3C`, date-stamps record+0x04 and calls source recipient router `0x413020` to append to each qualified user+0x6B4. Original NEXT `0x43215E` and PResults `0x4A8070` invoke date-bounded pending processing `0x613EE0`; later manager-wide mailbox maintenance invokes `0x5CF990`. Some record classes use +365 date-unit retention, a verified counterexample uses +21. Never interpret *queued* as *already delivered*.
3. **Inbox view**: `PEAMail::0x472680` builds a **separate filtered array** at panel+0x68/count+0x6C from the selected manager's linked mailbox. `0x472880` selects original comparison functions based on five sort controls; no generic cross-category date merge. `CMessageList` is 545×160 at **panel-local (233,30)**, 8 visible rows at 20px pitch, each `PMessageRow` background 532×18. ### Concrete integration hazard and severity

The clean-room read-only two-family source queue has **queue-local indexes, not original mailbox-node identity**. A naïve presenter mapping its `queue_index` to an inbox selected row would lose original cross-family ordering and stable polymorphic identity, and could show **not-yet-due** transfer requests as delivered. The current code explicitly presents these as source queues and **does not itself claim to do that**. This is an **P0 integration precondition / conditional design risk**, **NOT a newly observed GUI regression**. The existing missing EAMail host is the confirmed P0 defect. Reclassify no correctly fail-closed source seam as a current bug.

The new atomic NEXT transaction is a useful place to incorporate source event processing, but this audit **does not claim the source original uses deep-copy rollback** or that a copy is already fast enough on the full canonical database. The original scheduler may deliver EAM during/after NEXT/PResults via verified site ordering, not at arbitrary inbox open time.
