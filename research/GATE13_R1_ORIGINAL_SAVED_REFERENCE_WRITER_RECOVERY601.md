## Native independent save AND load of the original two calendars

- Native original high-level save path **`0x50DC69→0x50DC6E`** passes owner pointer `0x947AD8` and invokes full calendar writer `0x616470`. The subsequent **`0x50DCA4→0x50DCA9`** passes independent owner `0x947AF0` to the same writer. Neither is a Python fixture enum: these are real original global objects with their own event IDs/counters, list arrays and registered pointer tables.
- Matching original high-level load path **`0x50E09E→0x50E0A4`** invokes full calendar reader `0x616500` on `0x947AD8`, then **`0x50E0BB→0x50E0C1`** invokes it on `0x947AF0`. Stream separators/other fields exist between operations; no assertion of a complete original save-file format.
- `0x616470` writes per-date source event lists in two phases, using `0x616080` which dispatches event vtable+0x1C and `0x6160E0` which dispatches vtable+0x20. `0x616500` reverses into typed original events through `0x6163E0→0x616100` and a second pointer/flag restoration pass `0x616450` dispatching vtable+0x24. These are save/load passes, **not** original gameplay `0x6168C0` PResults passes.

## Source original event+8 reference writer inverse of previously proven loader

Original common vtable+0x20 writer **`0x5107F0`** saves current native source event DWORD+0x10 first, then checks the ACTUAL event+8 pointer. On NULL it emits saved link DWORD `0xFFFFFFFF`. On non-NULL it reads target's native event ID at target+0x0C, executes x86 **SIGNED `SAR ECX,1`** and emits resulting DWORD as the target's registry index. It does **not** save a raw source process pointer. For target ID `0x80000000`, saved index is `0xC0000000`, not unsigned `0x40000000`. For target ID `0xFFFFFFFF`, non-NULL target serializes index `0xFFFFFFFF`, colliding with native NULL sentinel; this is a real bytecode arithmetic edge case, **not proof** that real saved games ever reach that ID. The source does not explicitly check same-family link target parity; a source-only writer must not promise unsupported cross-calendar link reconstruction.

This perfectly matches native common **`0x510900`** loader from PR689: saved `0xFFFFFFFF` becomes source event+8=NULL; otherwise current event+0x0C bit0 chooses original 0x947AD8/0x947AF0 registry+0x10 and saved index fetches a source object pointer. The symmetric helper requires a verified native source event record, its actual nonzero event+8 DWORD, an explicit matching original target address, a readable target native original record and authentic native +0x0C ID. Missing target/registry provenance does not default to a different source pointer; null pointer **rejects** a supplied target.

The seven type0–6 restored event classes' authenticated native vtable+0x20 methods are `0x510840` for type0, `0x510850` for ordinary 0x50-byte matches (types1 and6), and `0x5108B0` for extended 0x5C-byte matches (types2–5). All invoke base `0x5107F0`. Source `0x510850` saves actual match flags DWORD+0x44, WORD+0x3C/+0x3E/+0x40, and DWORD+0x48. Source `0x5108B0` calls `0x510850` and adds native bytes +0x58..0x5B. This exactly pairs with loaded `0x510970` and `0x5109D0`. No assumption that flags remain static during later original NEXT/match/PResults callbacks.
