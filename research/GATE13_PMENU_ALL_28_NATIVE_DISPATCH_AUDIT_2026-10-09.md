## Major original-source findings

- **CONFIRMED: 9 root categories** in the source top-level array `0x947638`, construction order: Team `0x2`, Transfers `0x3`, Calendar `0x259`, TABLES `0x6`, Analysis `0x7`, ADMIN `0x4`, ACCOUNTS `0x5`, EAMail `0x1`, GAME OPTIONS `0x8`. A root category is **not itself** an ordinary destination panel.
- **CONFIRMED: 28 individual child entries** (Team 6, Transfers 3, Calendar 2, TABLES 2, Analysis 3, ADMIN 5, ACCOUNTS 3, EAMail 1, GAME OPTIONS 3). Each has one distinct native factory case. Calendar root and child both use ID `0x259`, distinguished by row kind/native tree position.
- **CONFIRMED executable control:** child action `0x47AD60` resolves the node via `0x60CA70`, rejects bit-0-selected or bit-1-gated nodes, calls factory `0x47AEC0(menu_id,0)` at `0x47ADB9`, and after a non-null return proceeds to panel stack `0x5ED2A0`, clears selected bits in tree and owner-refreshes via `+0xA8`. The specific `0x323` special case calls `0x4C3280` and then exits at `0x47C9C3` without regular factory panel return; its distinct resulting side effects must be retained. PMenu button release/hover/keyboard, disabled bits, popup dismissal, frame/timing equivalence are NOT fully verified in a live original interaction.
- **CONFIRMED original four-range jump tables and three special direct cases:** low `0x65..0xCE`, byte table `0x47CA04`, targets `0x47C9E4`; second `0x12D..0x193`, byte table `0x47CA8C`, targets `0x47CA70`; third `0x195..0x25B`, byte table `0x47CB14`, targets `0x47CAF4`; fourth `0x2BD..0x323`, byte table `0x47CBF8`, targets `0x47CBDC`; direct cases `0xCF` at `0x47B234`, `0x194` at `0x47C0B9`, `0x25C` at `0x47C724`. Sparse intervals outside accepted ranges fall through to `0x47C932` default Squad; do not assume unmapped IDs correspond to user-facing children.
- **CONFIRMED RETURN TO MAIN MENU is exceptional:** `0x323 -> 0x47C928 -> call 0x4C3280` followed by jump to factory cleanup `0x47C9C3`. Constructor `0x4C3280` installs vtable `0x7C64E0` at `0x4C3341`; RTTI COL `0x7E64F8`, descriptor `0x81E108` resolves to **`.?AVPStartMenu@@`**. It creates/enters the original start-menu and stack owner path, **not a normal `build_management_panel_snapshot` route**. The exact saved-game/exit confirmation sequencing in `0x4C3280` still needs full CFG and interactive verification.
- **CONFIRMED SAVE GAME is a distinct UI factory case:** `0x321 -> 0x47C889`, allocates `0x9FC`, invokes `0x4802F0` and `0x480660`. Base vtable `0x7C35D4` has RTTI `.?AUPLoadSaveGameBase@@`. Exact screen/dialog type and Save vs Load behavior require downstream verification; do not conflate it with the user-facing `RETURN TO MAIN MENU` action.
- **CONFIRMED SETTINGS `0x322` also constructs an original UI object** through `0x47C8DD -> 0x46A120`, geometry/helper `0x4802C0`. This original target is NOT equivalent to the deferred modern Settings extension.
- **CONFIRMED EAMail `0x65 -> 0x47B1D0 -> 0x474B10`**, RTTI `PEAMail` vtable `0x7C2950` and child `CMessageList` vtable `0x7C2A50`, still has no integrated clean host destination.
