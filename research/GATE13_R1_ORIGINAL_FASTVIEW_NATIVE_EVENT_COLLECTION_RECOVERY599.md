## The actual original nested FastView per-frame event pipeline

The native original 0x51F490 nested object installs vtable 0x7CA58C; its second virtual entry (+4) is **0x51F9F0** (independently checked actual vtable DWORD 0x7CA590 = 0x51F9F0). This callback uses the real saved match pointer [nested+0x2A8] via original 0x62AC80, then native **0x5112E0** reads owner+0x4C and invokes its vtable+0x30, masks EAX with 0xFF. This external virtual return is a BYTE (zero versus any nonzero), not an invented FastView game setting.

Original 0x51F9F0 uses distinct global buffers with no source array bounds checks:
- If 0x5112E0 AL is nonzero: reads DWORD active cursor at 0x9847FC, base at 0x947AF8, and pointer array at 0x947AF0; computes unsigned native index (cursor-base) then reads DWORD element at array+4*index.
- If source AL is zero: uses the SAME 0x9847FC cursor but native base 0x947AE0 and pointer array 0x947AD8.
- Calls **0x51FA70** with this exact selected native event RECORD pointer and original owner 0x62AC80. It cannot be substituted by a calculated score, random past event, game date, or a top-league fallback. A missing/null pointer or out-of-bound source index is a safety failure; reconstructed code must not read invalid native memory.

At 0x51FA70, native selected event pointer EDI is **seeded as the first candidate** at nested owner +0xA4 and count owner +0xA0 is set to one. Its linked event cursor calls original virtual+0x18 to obtain each next event record. Each candidate can append only after source gates:
1. Candidate record DWORD+0x08 must be zero; record DWORD+0x44 bit 6 (0x40) must be clear.
2. Candidate pointer equal to the initially selected event pointer does not append. This source branch also tests whether both involved clubs are human via 0x4037B0, changing other display flags, not modeled by this list-only projection.
3. Other candidate must have original DWORD+0x4C equal to the selected event's actual pointer at +0x4C. Native 0x510C30 then runs; a **nonzero** result suppresses ordinary append and changes another flag. Its meaning remains unresolved and MUST be separately supplied from the authentic runtime.
4. A remaining candidate with WORD+0x40 equal to 0xFFFF enters a special text construction branch and is **not** appended to this ordinary list. This special branch and distinct UI flags remain to be reconstructed before claiming the full view.
5. Otherwise, candidate source pointer is appended at original +0xA4 + 4*count, and native DWORD count +0xA0 increments. Original object region +0xA4..+0x2A3 can safely hold at most 128 DWORD pointers before selected-index owner+0x2A4; reject overflow rather than corrupting it.

The original next calls native 0x526DF0 to sort this pointer list using comparator **0x51F3C0**, then scans the reordered list to find the selected original pointer and writes its final index to owner+0x2A4. Native 0x51F3C0 obtains each event+0x14 virtual output, then indirect text+0x0C pointer to original NUL byte string; its byte comparator is strictly unsigned lexicographic and case-sensitive, returning 1 when the LEFT record's byte string is GREATER than the RIGHT record's (meaning the two should swap). Native 0x526DF0 calls the comparator with list-left and list-right and moves right toward the front on a nonzero return. The resulting list sorts ASCENDING even though the predicate is `left > right`. It has no Unicode, case-fold, locale or modern normalized-name sort. The source does not guarantee a stable deterministic tie ordering from 0x526DF0 when different records have equal original indirect names; the safe projection refuses such ties rather than choosing a fabricated deterministic tiebreaker. Distinct source-proven names yield an unambiguous ordering and selected ordinal. The complete 0x51FA70 remaining linked record callbacks, UI texts, and frame rendering ARE NOT reconstructed.
