## Verified native owner, reachability and branches

- Original `0x513010` invokes match vtable +0x38 then +0x3C. Seven source-vetted LeagueMatch v+0x3C implementations directly or through wrappers invoke common `0x511370`. At `0x511381`, `or DWORD PTR [match+0x44], 1` sets started bit0. At `0x511385`, source **unconditionally** invokes `0x5112E0`. This routine reads the match's **competition-owner pointer at +0x4C**, calls **that object's** vtable+0x30 and masks its EAX result to its low byte (`and eax,0xff`). It does NOT dispatch the LeagueMatch's own vtable+0x30.
- When this **initial** competition virtual+0x30 result AL is nonzero, `0x511392..0x511426` invokes match SideRef getters, global club owner callbacks, optional `0x50EA40` and might write associated world/owner +0x68. These effects can modify world or context **before** the next gate. A zero AL bypasses these early calls. An original native match snapshot used for the reschedule gate must therefore be supplied **at address 0x511429**, after those potentially mutating effects; the model never supposes that the snapshot from before 0x511370 is equivalent.
- At `0x511429` native `match+0x44` **bit5 = 0x20** is tested. If set, source branches to `0x51144A`, **skipping the second `0x5112E0` and `0x5127A0`**. When bit5 clear, it calls `0x5112E0` again at `0x511434`: original reached AL **zero** calls rescheduling `0x5127A0` at `0x511443`, nonzero skips it. This independent second return cannot be assumed identical to the first since earlier source callbacks may have executed.
- Regardless of skip or rescheduling call, `0x51144D` calls `0x512710` and `0x511456` calls `0x512230` with processing owner. Subsequently `0x51145B..0x511D26` branches through substantial additional owner, team, club, date and event work. **A correctly projected gate is neither a completed event nor a complete v+0x3C native post-match callback.**

## Actual native first rescheduling-calendar request

- `0x5127A0` begins a **two-iteration** EBX=0,1 team/event ownership loop, not a simple date update. For the first pass EBX=0, `0x5127B7` reads DWORD `[processing owner+0]` into EBP as first native team/event owner pointer.
- `0x512822` reads a *source global date index* DWORD from `0x9847FC`; `0x512828` forms `date+1` with uint32 wrap. At `0x512830` original `0x510300` dispatches **two separate event registries** using `match+0x0C` bit0: set -> `0x947AF0`, clear -> `0x947AD8`. At `0x512838` the original invokes `0x615D10` on that registry with first owner pointer, date+1 and the literal `1`. It consumes the returned event pointer and performs further mutable native world/fixture/player work. Neither `0x615D10` return value nor resulting insertion is established from only these inputs. The later second EBX=1 pass is still unresolved.

## Implementation and qualification

`reconstruction/original_native_v3c_reschedule_gate.py` introduces two strictly bounded, read-only typed receipts:

1. `source_original_v3c_511429_reschedule_gate` requires an original native LeagueMatch vtable and post-bit0 record through +0x4C, nonnull original competition owner pointer, and the **actual separately reached** first and (only when bit5 clear) second `0x5112E0` return EAX. It masks low-byte semantics, distinguishes the first possibly mutating SideRef branch, identifies precisely when `0x5127A0` was called, and always lists the still-unperformed `0x512710`/`0x512230` callbacks. Skipped virtual-return inputs are rejected.
2. `source_original_5127a0_first_calendar_request` accepts only a receipt that **actually reaches** rescheduling, original processing owner bytes with a nonnull first DWORD, and the real reached global date index. It returns the original registry address, first requested date, first native owner pointer and literal lookup argument, **not** an invented calendar insertion or second-pass schedule.

Regressions validate three different native vtable owners, first/second return divergence and masks, bit5 short circuits, every primary/secondary registry bit0 combination, missing original owners and return values, zero/nonzero/overflow inputs, uint32 date wrap, and a positive composition through the already-recovered source-original v38 zero-event score latch and first v3C flag write.
