## Original 0x510380 source event owner and identity

Original `0x510380` starts from actual source collection pointer passed as arg0 (EDX). It checks **exact pointer identity** `EDX==0x947AF0`, stores its 0/1 result at native event DWORD+0x0C bit0, and uses the original collection's DWORD+0x0C serial index. It shifts serial left 1 and ORs the selected collection bit to produce **node+0x0C = 2*serial + (collection==0x947AF0 ? 1:0)**. It writes original event DWORD+0x08=0 and +0x10=0xFFFFFFFF, sets base vtable `0x7C4D70`, then **increments the actual source collection's own +0x0C serial**. The child LeagueMatch constructors later replace vtable (six common variants+one special) as previously authenticated. Source initial DWORD+8 zero is real for a **freshly constructed** event; it cannot be promoted to all saved/reloaded/native event objects without load-path evidence. A source event ID carries two independent event-container identities and sequence numbers; do not flatten to a match fixture ID or date bucket number.

Original `0x5103D0` calls `0x4F3B50` to resolve the source collection pointer from constructor inputs, then enters `0x510380`; `0x5104D0` finalizes one base LeagueMatch vtable `0x7C4CE4`, `0x510500` replaces with `0x7C4C24`, `0x510520` with `0x7C9D9C`, `0x5105A0`/`0x5105D0` with `0x7C9E14`, `0x510600` with `0x7C9E80`, `0x510640` with `0x7C9EF8`, and `0x510680` with special `0x7C9F70`. These exact native **constructor wrappers are source-class distinctions** but no proof yet that each maps directly to an unqualified reconstruction `node_kind` string. The native `0x5103D0` also initializes source Side components from input, which require independent original ownership before host gameplay.
