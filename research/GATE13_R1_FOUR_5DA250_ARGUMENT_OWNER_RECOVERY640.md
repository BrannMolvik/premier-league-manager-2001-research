For stages2–4, no corresponding current-stage B setter appears on the nonhuman branch; B remains whatever the actual source stack holds from earlier reached producers. **This is not permission to infer B=the fresh 5E48D0 callback, to assume it is zero, or to claim every possible previous stage wrote B.** Original earlier stage skips/initialization, inherited stack snapshot, and x87 control-word treatment remain to be source-qualified.

## Source continuation: zero-flag 5E43B0→5E48D0 constructor and QWORD return

The original first scored stage at `5DA995`, second at `5DAC28`, third at `5DAEA6` and fourth at `5DB124` all construct a five-PUSH sequence: `PUSH 0`, `PUSH 0`, `PUSH 1`, two original stage-context DWORDs, then call native `5E43B0` with ECX pointing to a temporary object at source stack+0x34. The exact contiguous signatures of all four stage construction and two-function call chains were independently checked. Native `5E43B0` initializes its input QWORD and offset+8 metadata and returns with `RET 0x10`: it consumes **four** argument DWORDs, intentionally leaving the earliest `PUSH 0` as the outgoing argument for the immediately following `5E48D0`. Its `RET 4` cleans that last flag. No intervening push/reset occurs.

Native `5E48D0` at 0x5E48D0 loads `EAX=[ESP+4]`, then `FLD QWORD [ECX]`; if EAX=0 it takes the branch at `5E48D8` and directly returns the x87 QWORD value. This is a calling-convention/source-control result, not proof the original `5E43B0 → 5E4300 → 5E4410` constructor computes any particular decimal number. Its intermediate initialization/selected mode-dependent x87 math and FPU CW are still unresolved. The four stage callback QWORDs remain **conditionally copied into B** under the human gate as described above; do not conflate an always-returned callback result with an always-written B stack slot.

## Source continuation: exact scorer B constructor owner and lazy global factor

An additional original static disassembly of `5E4300, 5E43B0, 5E4410, 5E48D0` establishes the four scored-stage callback QWORD creation as a **source-bounded x87/scaling path**, not a generic arbitrary input.

At each four-stage `5E43B0` call, the four consumed argument DWORDs are the selected source two input DWORDs, native mode **1**, and a separate **0** which `5E43B0` reads at original `[ESP+0x10]` and writes to its temporary object **+8** at `5E43B7`. Its nested `5E4300` then checks mutable global QWORD **0x87AD88** against original zero using x87 FCOMP/FNSTSW; when the original equality status is set, it calls `6596A0` to obtain an unsigned native category 0..4 and writes one of five source QWORD factor bit patterns to 0x87AD88 (out-of-range category returns without selecting a literal). At arbitrary later lifecycle points the global can only be called known if its actual earlier mutations are source-traced; the canonical selector and zero-filled loader state are independently established in the correction below.

`5E43B0` calls original `5E4410` with native mode **1** at `5E43D0`. Source `5E4419` tests the actual mode and, when nonzero, `5E442B FLD QWORD [0x87AD88]; 5E4431 FMUL [EBP+8]; 5E4434 FSTP [original temporary+0]`. It then FCOMPares the temporary QWORD against zero and, on positive/nonzero ordered result, observes the temporary object **+8 is zero** at `5E445A/5E445F`, branching directly to the shared `5E4821` return. For nonpositive or unordered x87 statuses it already branches to that shared return at `5E4454`. Thus the mode-specific alternate 5E4410 numeric branches are unreachable **for these four original scorer calls**, without claiming their other callers cannot reach them.

The caller's retained first zero argument then reaches `5E48D0` which FLDs the temporary QWORD directly; no `FDIV [0x87AD88]` occurs. Source order is: **native callback stage input QWORD → lazy original global factor 87AD88 → x87 FMUL → FSTP temporary QWORD → FLD temporary QWORD → scorer FSTP to local+0x20 (or stage1 directly to local+0x38)**. Due to unknown original CW/RC, global factor selection, constructor arguments and potential intervening callbacks, the exact result remains **SOURCE-TRACED, NOT NUMERICALLY IMPLEMENTED**. Original 5E4300/5E43B0/5E4410 opcode guards added (nine more sites), independently checked locally against the canonical executable: cumulative **44 verified PE opcode sites** on this WIP feature branch. ### Recovery641 additional x87 integer conversion evidence

Independent canonical PE disassembly identified original `0x668350` as the conversion repeatedly invoked **nine times** in this same four-stage score region: `5DAA00` on stage1 nonhuman `FLD B`, and pairs `5DABCA/5DABDB`, `5DAE45/5DAE56`, `5DB0C6/5DB0D7`, `5DB341/5DB352` on the four scored-stage threshold/RNG paths. It saves the caller x87 control word via `FSTCW [EBP-2]`, then `OR AH,0x0C` sets both rounding-control bits to **RC=11 (toward zero)**; it loads this temporary via `FLDCW [EBP-4]`, executes `FISTP QWORD [EBP-0xC]`, restores the original x87 control word via `FLDCW [EBP-2]`, then returns the 64-bit integer in EDX:EAX. All nine original CALL rel32 targets and the exact 39-byte helper were checked directly. It therefore rounds to signed integer **temporarily with truncation**, not according to a guessed ambient nearest rounding mode. Range overflow/NaN/inexact FPU exception behavior and how the caller uses low vs full integer remain context-dependent; do not replace the original helper with generic Python round. In particular, this **does not** prove the CW/PC/RC of the earlier `5E4410 FMUL` or `5DA250` scorer itself, since `668350` restores the incoming control word.
