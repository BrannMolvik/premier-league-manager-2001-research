## Source-audited native stage callsite owners

For each of four entered, independently status-gated native scoring regions, let S be the actual ESP **before** the original four scalar argument PUSH instructions. Despite two distinct push sequences, at callee entry `0x5DA250` the first eight-byte argument A at `[ESP+4]` equals the original pre-push **[S+0x30..0x37]**, and the second eight-byte argument B at `[ESP+0xC]` equals **[S+0x38..0x3F]**. Calls are `5DAB07`, `5DAD84`, `5DB003`, `5DB280`. Stage1/3 use PUSH B.high, B.low, A.high, A.low with the intervening shifting offsets; stage2/4 preload B.high/B.low/A.high before PUSH B.high, read A.low from the shifted stack, and PUSH B.low,A.high,A.low. The original 5DA250 returns an x87 ST0 result and callee pops 16 bytes. Do not confuse stage-indexed scoring local QWORDs with these two arguments.

**Human branches:** each original 4037B0 human-club predicate conditionally calls 403850 selected-user lookup and uses the native selected `user+0x694` pointer. Stage1/2 use its signed DWORD **+0xC**; stage3/4 use signed DWORD **+0x8**. FILD followed by FSUB the reached callback QWORD gives A, FSTP into [S+0x30]; this is x87 source flow, not a bit-exact Python formula. Stage1 always stores the original 5E48D0 callback QWORD directly into B at 5DA9AD. Stages2/3/4 store callback at [S+0x20] first and **only on human branch** copy both DWORD halves into B at [S+0x38/+0x3C]; the native instructions are 5DAC57/5DAC5D, 5DAED5/5DAEDB, and 5DB153/5DB159.

**Nonhuman branches:** at `5DA9F0/5DA9F8`, `5DAC79/5DAC81`, `5DAEF7/5DAEFF`, `5DB175/5DB17D`, the source writes **both DWORDs of A to 0**, not a derived football value. At stage1 the callback already established B unconditionally. For stages2–4, no corresponding current-stage B setter appears on the nonhuman branch; B remains whatever the actual source stack holds from earlier reached producers. **This is not permission to infer B=the fresh 5E48D0 callback, to assume it is zero, or to claim every possible previous stage wrote B.** Original earlier stage skips/initialization, inherited stack snapshot, and x87 control-word treatment remain to be source-qualified.

## Source continuation: zero-flag 5E43B0→5E48D0 constructor and QWORD return

The original first scored stage at `5DA995`, second at `5DAC28`, third at `5DAEA6` and fourth at `5DB124` all construct a five-PUSH sequence: `PUSH 0`, `PUSH 0`, `PUSH 1`, two original stage-context DWORDs, then call native `5E43B0` with ECX pointing to a temporary object at source stack+0x34. The exact contiguous signatures of all four stage construction and two-function call chains were independently checked. Native `5E43B0` initializes its input QWORD and offset+8 metadata and returns with `RET 0x10`: it consumes **four** argument DWORDs, intentionally leaving the earliest `PUSH 0` as the outgoing argument for the immediately following `5E48D0`. Its `RET 4` cleans that last flag. No intervening push/reset occurs.

Native `5E48D0` at 0x5E48D0 loads `EAX=[ESP+4]`, then `FLD QWORD [ECX]`; if EAX=0 it takes the branch at `5E48D8` and directly returns the x87 QWORD value. With nonzero EAX it divides by QWORD global `0x87AD88` via `FDIV` at `5E48DA`. **All four actual scored-stage callers prove EAX=0**, so the optional `FDIV` is not reached in those four calls. This is a calling-convention/source-control result, not proof the original `5E43B0 → 5E4300 → 5E4410` constructor computes any particular decimal number. Its intermediate initialization/selected mode-dependent x87 math and FPU CW are still unresolved. The four stage callback QWORDs remain **conditionally copied into B** under the human gate as described above; do not conflate an always-returned callback result with an always-written B stack slot.
