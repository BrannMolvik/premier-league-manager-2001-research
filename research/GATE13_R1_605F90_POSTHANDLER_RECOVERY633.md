## Corrected original owner finding

**Important correctness correction:** earlier runtime handoff called `0x417380` a “club+6B8” lookup. Actual native `0x417380` returns a pointer into a **registered human USER-owned** indexed table. It is not a direct DBRClub+6B8 write. The exact reached graph:

- Original `0x605FEE`: after selected `0x6060E0/0x6061F0/0x606290` **handler returns**, global `0x875644` vtable first getter reads the **third separately reached player pointer** for original `0x417340` registered-manager predicate. `TEST AL,AL` at `0x606000` and `JE 0x60601A` on AL=0 skip all subsequent source steps, returning `AL=1` regardless. This is **not** proof the native handler actually ran, of successful event insertion or of its post-handler heap/descriptor cleanup.
- On AL=1, `0x606004` resolves the **fourth** actual native player pointer separately (not necessarily identical snapshots after dynamic virtual code). `0x606011 CALL 0x417380`, then `0x606016 MOV BYTE PTR [EAX+0x24],0`.
- `0x417380` first calls `0x4172D0` (signed player+0x10 CURRENT-club lookup `0x417270` → `0x403850`). `0x403850` uses native registered manager predicate `0x4037B0`, then original `0x413B40` matches that club's key against global `0x874C10+0x9CC` linked-user nodes; `0x413B6D MOV EAX,[EAX]` returns the **matched registered user pointer** (or zero on no registered user). `0x417389 MOV EDI,[EAX+0x6B8]` reads the table pointer from that user. Do **not** use `DBRClub+6B8`; that would write unrelated or invalid memory.
- `0x417391` loads signed player+0x10 and pushes it as the argument to `0x41E3D0`, whose `0x41E3D0/0x41E3D4` reads and compares the **same** player+0x10 value. Because the branch compares equal, `0x41E3DA MOV AL,[ECX+0x70]` always selects unsigned byte player+0x70 on this actual call (rather than +0x76). `0x41739B` masks 0xFF and `0x4173A0–0x4173A6` calculates `returned_user_table_pointer + 200*(selector-1)`; `0x606016` clears the selected 200-byte source record's +0x24. This is source-proven pointer arithmetic only, not a valid table allocation extent or guaranteed successful native write.
- The source has no bounds check for selector 0: it computes table pointer **minus 200 bytes**. The reconstruction source-only projector explicitly rejects it while its actual allocated extent is unresolved; this does **not** claim the original guarded zero. Likewise independently verify every record pointer and reject 32-bit arithmetic overflow. The output native byte-write flag stays false.
