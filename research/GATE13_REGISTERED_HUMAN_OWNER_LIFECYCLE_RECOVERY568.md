## Original direct instruction evidence and lifecycle

Native `0x412CD0` initializes process-global `0x874C10`. At `0x412D04` it writes literal **1** to its registered-human list payload-ownership flag **`+0x9C8`**, and at `0x412D0E` clears the linked-list head `+0x9CC`. The native registered-human count `+0x9D4` and current selection index `+0x9C4` both initialize to **0** at `0x412D94` and `0x412D9A`. This is genuine source initialization, not inferred from a GUI.

Normal TeamSelect club selection `0x4D8EF8 -> 0x413BB0` first scans existing linked nodes for the SAME original club object; if already present it returns 0 without creating another DBRUser. Otherwise it allocates an original 0x10F0-byte user at `0x413BEF`, appends the new pointer in its 0xC-byte node to `+0x9C8` via `0x413C44/0x413C4A -> 0x617D70`, initializes the user/name/manager, then at `0x413C60..0x413C71` sets current index to the PREVIOUS registered count and increments count. This is distinct from staff staging and the SupportStart modal.

Original TeamSelect **deselection** at `0x4D90AD..0x4D90C8` identifies the selected existing original club record then invokes `0x413B80` to find the corresponding user's linked-list index and `0x413DB0` to unlink it. Native `0x413DFB -> 0x414680` first invokes unlink helper `0x42CBF0`. Source `0x414692` tests **the list owner's payload-deletion flag**, not the staff selector flag or SupportStart Apply result. If it is nonzero, `0x41469F` invokes **`0x424FC0` the original user payload destructor**, then `0x4146A5` frees that user payload allocation. The 0xC-byte list node itself is freed at `0x4146AE` **regardless** of the owner flag. Source `0x413E00..0x413E0D` decrements human count and sets current index to **count-1**, including **-1 after removing the last human**, even though fresh constructor initializes current index to 0. Original destructor `0x424FC0` sets user staff list payload owner flags `+0x5B8,+0x5C4` to 1 and `+0x5D0` to 0 before its deeper teardown (see Recovery567). The exact transitive staff/global and event queue effects remain unverified.

This closes the **bounded fresh-world owner-flag ambiguity**: the native new-game registered-user owner is initially payload-owning=1. It does not prove all alternative saved worlds, indirect setters or later callback effects retain that value, nor does it make SupportStart Cancel a deselection. `0x413B80` assumes a real matching club pointer; the reconstruction fails closed when caller supplies a missing club rather than inventing an impossible removal.
